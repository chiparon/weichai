# 国创首轮检索与上下文实验

展示用的平均响应时间对比、图表及数据表见 [检索策略与响应效率展示](strategy-efficiency-demo/README.zh-CN.md)，采用无内容上限、相同输出的串行与并行混合检索对照。

本页保留旧版首轮数据。最新 Context 构建调整、简单指标和上下文样例见 [Context 构建验证](context-construction.zh-CN.md)。

运行时间：2026-09-09 16:52 至 16:55（北京时间）。生产代码基线为 `4f258b1`，分支为 `codex/guochuang-ui`，包含 PR #33。

## 实验设置

- 语料：Commons FileUpload Java 原工程和 TypeScript 适配工程，复用 2026-09-08 发布的固定 E5 索引。本轮不重新建库或生成模块。
- 任务：6 类功能在两种语言中的 12 个定位任务，涉及文件名校验、Base64、Quoted-Printable、字符集、临时文件清理和分段请求头。标注来自源码检查，尚未经过独立人工复核。
- 查询：自然语言需求，函数粒度；每题只检索对应工程，目标符号和源码位置不进入查询。
- 向量：384 维 `Xenova/multilingual-e5-small@761b726dd34fb83930e26aab4e9ac3899aa1fa78`，本机推理，使用 `query: ` / `passage: ` 前缀。
- 对照：完整任务检索，以及关闭依赖扩展。后者只将依赖邻居查询替换为空结果，召回和上下文编译器保持一致。
- 预算：1,000、2,000、4,000、8,000 Tokens，每组重复 3 次，共 288 次测量。每题预热一次后串行请求，轮换配置顺序。索引生成和模型冷启动不计入查询耗时。
- 指标：主要结果按精确符号匹配；源码覆盖按标注的文件和行范围计算，允许包含该函数的类源码覆盖标注。每题只有一个排名目标，因此 Recall@10 在这里等同 Hit@10。

## 首轮结果

每个配置包含 12 题、36 次请求；重复运行用于观察耗时，独立任务数仍为 12。下表使用校正后的源码范围计分。

| Token 预算 | 配置 | Hit@10 | 标注实现范围覆盖 | 平均耗时 | P95 耗时 | 请求错误 |
| --- | --- | --- | --- | --- | --- | --- |
| 1,000 | 完整检索 | 25.0% | 0.0% | 605 ms | 1,131 ms | 12 / 36 |
| 1,000 | 关闭依赖扩展 | 58.3% | 0.0% | 211 ms | 295 ms | 0 / 36 |
| 2,000 | 完整检索 | 58.3% | 16.7% | 813 ms | 1,792 ms | 0 / 36 |
| 2,000 | 关闭依赖扩展 | 58.3% | 16.7% | 245 ms | 366 ms | 0 / 36 |
| 4,000 | 完整检索 | 58.3% | 25.0% | 870 ms | 1,792 ms | 0 / 36 |
| 4,000 | 关闭依赖扩展 | 58.3% | 41.7% | 252 ms | 357 ms | 0 / 36 |
| 8,000 | 完整检索 | 58.3% | 66.7% | 927 ms | 2,113 ms | 0 / 36 |
| 8,000 | 关闭依赖扩展 | 58.3% | 58.3% | 258 ms | 345 ms | 0 / 36 |

在 2,000 Token 以上，两组主要结果均命中 7 / 12 题，说明增加上下文预算未解决候选漏检。4,000 Token 时，完整检索覆盖 3 / 12 个目标实现，关闭依赖扩展覆盖 5 / 12；8,000 Token 时，完整检索多覆盖一个目标实现，但未增加“主要结果命中且源码已覆盖”的题数。需要进一步检查依赖片段和整类源码的选择顺序及其预算占用。

1,000 Token 下，完整检索的四个 Java 任务每次均返回 HTTP 400。单独复查 `java-charset` 得到内部错误：`The token budget is too small for the task and snapshot metadata.`。全部失败保留在统计分母，其他三个任务的内部原因尚未逐项复查。

本轮必要证据只标注目标实现，没有完整标注任务所需接口、配置和测试。因此该消融用于定位实现交付和预算问题，不能单凭此表评价依赖扩展的全部收益。任务检索成功也不等于 Coding Agent 完成开发任务。

## 复现

启动已有 SeekDB，并使用仓库脚本运行上述固定版本 E5 服务后，在仓库根目录执行：

```bash
node --import tsx scripts/run-guochuang-pilot.mts --budgets 1000,2000,4000,8000 --variants full,without-dependencies --repeats 3
```

脚本从 `services/retrieval-service/.env` 读取数据库账号，从指定数据库获取已发布版本，并在查询前解析和保存固定符号标注。默认数据库为 `forexplore_task_context_dev_20260908`；默认输出到带时间戳的新目录。实验通过本机 HTTP 入口调用生产检索和评测代码，不修改已有索引。上述命令在当前代码上重跑预算对照；本页历史结果对应旧版实现，源码及行数限制也与当前版本不同。
