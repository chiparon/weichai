# 插件后端与跨仓取证修复

从仓库根目录运行 `npm run dev:extension`，在扩展开发窗口打开 RECAST。已经打开的旧扩展窗口需要执行 **Developer: Reload Window** 才会加载新构建。

## 自动启动与模型配置

- 在可信工作区首次打开工作台时，宿主启动扩展自带的 adaptation 后端。分析、模块规划、任务重排、模块重排和翻译会按需检查后端。
- 外部后端配置地址默认是 `http://127.0.0.1:8788`；显式 `forexplore.adaptationApiUrl` 设置优先，否则跟随 `ADAPTATION_PORT`。自动启动的自有子进程监听端口 0，由系统分配空闲端口并通过 IPC 回报；实际地址见 RECAST 输出。仅本机 HTTP 根地址支持自动启动。
- 后端绑定启动时的目标工程；如果更换目标工程或端口，请关闭原扩展开发窗口并重新启动。这样不会中断旧目标的翻译并把后续修改发往错误目录。
- 重复调用共用一次启动。关闭窗口时只停止本窗口启动的子进程；外部后端只有在目标根目录、语义查询地址、能力和翻译令牌均匹配时才可复用。公共 `/health` 成功不能把鉴权失败改成已连接。自有进程的已验证身份缓存 30 秒，瞬态探测失败先重试；仍未响应但进程存活时显示待确认提示，下一次使用时重查。进程退出立即清除缓存。
- API Key 仍按配置地址保存在 SecretStorage，运行时只向已验证的实际端口发送；动态端口变化不要求重新输入密钥。
- 设置面板中的 Provider、API Base、Model 与 API Key 现在也用于任务与模块重排。Key 由 VS Code SecretStorage 每次请求读取，经本机请求传入后端，不写入工作区、命令行或日志。修改配置后后续重排立即使用新配置。
- 模型重排是受约束的模型调用，返回候选 ID 排列；翻译 Agent 才负责多轮规划、取证、修改与验证。重排失败时任务检索记录 `CONTEXT_RERANK_UNAVAILABLE`，不能将回退结果当作模型重排成绩。

`forexplore.backend.autoStart` 默认开启。自动启动仅包含 adaptation 模型后端，SeekDB 和 embedding 服务仍需按原部署流程配置。开发模式的内存索引不等价于生产向量检索。

### 2026-10-03 审阅后局部修复

- 文档编码同时限制每批 16 条与 16,384 字符，单个超预算输入独立处理。原始内容不按字符截断；本地 E5 tokenizer 已按 512 token 截断，错误地预截断会改变模型输入。服务端再按相近长度分组，减少短输入的 padding；每个小批结束后重新排队，其他请求可以穿插。正在执行的推理不能被抢占，这不是独立查询推理池。
- 原生解析 worker 明确报告就绪。单文件崩溃或超时会写入错误诊断并换 worker 继续；worker 未就绪或同一处理通道连续三次失败仍中止。用户取消不会转成单文件降级。
- 已验证的自有后端缓存身份、重试瞬态探测；明确鉴权拒绝及目标/语义端口不一致仍报错。自动启动端口通过子进程 IPC 回报，所有模型、规划、翻译入口使用实际地址，密钥存储仍使用配置地址作为稳定身份。
- `.apikey/` 已加入忽略规则，未读取或更改其中的密钥。

验证使用本机已有 Camel 完整索引中的 16 条长源码片段，模型权重离线加载到隔离进程，原索引任务继续运行。旧批次耗时 21,486 ms；分批后最长一次 2,004 ms，总计 21,449 ms。两边 tokenizer 窗口均为 512；q8 模型受批次组成影响，输出并非逐位一致，最小对应向量余弦相似度为 0.99095。这只验证单次等待预算与输入窗口，未证明检索排名不变或整体建库加速。

真实打包后端验收启动两个独立进程，取得不同系统分配端口；公共端口上的无关服务保持运行，两个后端均通过有令牌请求、拒绝无令牌请求。相关单元/集成测试和三个服务及扩展的类型检查通过。复现脚本和结果位于 `tmp/recast-acceptance-20261003/review-fixes/` 的 `embedding-benchmark.mjs/.json` 与 `backend-smoke.mts/.json`。

本轮没有重启用户的 Camel 索引或现有模型服务；源码与扩展后端构建已更新，当前进程仍运行原代码。不能将这组局部修复称为分钟级百万行验收：结构/全文先激活、后台向量就绪状态、同版本断点续写、孤儿任务恢复以及整库读取改造尚未实施。SeekDB、embedding、rerank 的依赖端口自动回退也不在这次 adaptation 子进程动态端口修复内。

### 端口与启动顺序

- 开发启动器先验证 SeekDB SQL 和 embedding/rerank 的实际模型健康状态，再打开宿主；不再与扩展争抢启动 adaptation，也不注入共享固定翻译令牌。`--skip-services` 仅用于自行管理依赖的部署。
- 语义查询默认使用本窗口独占的自动端口，实际地址在 RECAST 输出中可见，并传入后端。`FOREXPLORE_SEMANTIC_QUERY_PORT=0` 同样表示自动分配；固定端口被占用时明确失败，不借用另一窗口的仓库范围。
- 后端初始化会创建 `.forexplore/workspace-translations`，因此先完成该初始化，再捕获索引源码快照，避免目录创建与快照一致性检查竞争。后端启动失败不阻止随后尝试索引，但失败状态不会被公共健康检查覆盖。
- 依赖子进程提前退出时，`npm run services:up` 立即报告失败和日志路径，不再等待整个端口超时或将无关 HTTP 服务视为正常。模型下载需要可达的模型源；Windows 系统代理配置不等于 Node 已有可用代理。

## 编译与行为验收

默认编译助手识别 Python、Go、Rust 和 .NET 工程，并调用本机工具。其他工程使用用户设置 `forexplore.backend.compileCommand`，例如：

```json
{
  "forexplore.backend.compileCommand": {
    "executable": "python",
    "args": ["-m", "compileall", "-q", "src"],
    "timeoutMs": 120000
  }
}
```

需要业务验收时配置 `forexplore.backend.verification`：包含 `command`（同上结构）和非空 `protectedFiles`（工程相对路径数组）。编译与验收命令只读取用户设置，工作区不能替换宿主执行命令。未配置行为验收时，界面明确显示没有行为验证；语法编译成功不代表业务实现正确。

手动运行的外部后端如需用于翻译，先在 VS Code 用户设置中设 `forexplore.backend.autoStart=false`。在启动扩展前设置固定 `FOREXPLORE_SEMANTIC_QUERY_PORT`；后端启用 `ADAPTATION_SEMANTIC_INDEX_ENABLED=true`，将 `SEMANTIC_QUERY_PORT_URL` 指向该端口，并在 RECAST 输出中核对地址，不能直接假定为 8790。后端的 `ADAPTATION_PROJECT_ROOT` 和 `ADAPTATION_SKELETON_PROJECT_PATH` 必须绑定插件选中的目标根目录，两个进程须配置相同的 `ADAPTATION_WORKSPACE_TRANSLATION_TOKEN` 和可选 `SEMANTIC_QUERY_PORT_TOKEN`，再运行 `npm run dev:adaptation`。自动启动时宿主在内存中生成令牌并传递实际地址。

## 检索与取证范围

- UI、HTTP、MCP、Agent 取证和后端验证统一使用 64 个仓库版本上限。目标工程加 8 个历史仓库的 9 范围请求可以执行；超限明确拒绝，不再静默丢掉第 9 个及之后的仓库。
- 选择一个历史模块后，翻译 Agent 可按需查询当前窗口可见的全部已索引历史仓库。候选固定为所选版本，其他仓库固定为准备翻译时的活动版本。未完成索引的参考工程会阻止范围准备，避免交付一个看似完整的范围。
- 任务证据包中由宿主记录的参考仓库快照也会进入 Agent 的只读取证范围。隐藏仓库不会因共享索引存在而自动获得授权。
- 扩大的是读取范围；`writeFiles` 仍仅来自选中的目标模块。
- Python 绝对模块导入会在已授权快照的根目录和 `src` 布局中进行精确路径匹配，递归补充依赖文件。仅包含常量或初始化语句的中间模块也能继续遍历。关系记录包含来源、目标仓库及双方版本。
- 同名模块歧义不猜选目标；找不到目标、源码截断和遍历上限会记录缺口。当前新增的是 Python 静态导入关系，不能声称覆盖其他语言、动态导入或运行时调用图。

取证请求仍有文本、文件数、时间与源码行预算。范围完整表示授权仓库未被静默截断，不代表一次请求会返回全部源码。
